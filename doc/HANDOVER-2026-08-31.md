# Handover — 2026-08-31: deferred dynamic tools

klein's half of a two-repo change. The other half is rs-gallium's, and until it
lands this is inert by design: the setting defaults off, and a server that does
not implement the flag ignores it.

## The problem

An app-server thread takes its `dynamicTools` list once at `thread/start` and
keeps it for the life of the thread. Nothing updates it mid-thread — not the
protocol, and not gallium, whose `RemoteTool` doc says so outright ("Tools are
registered once per thread").

So every tool klein offers is paid for on every thread, forever. Measured:

| Offered | Tools | Spec JSON | ≈ tokens |
|---|---|---|---|
| klein's built-ins only | 20 | 12.8 KB | ~3.2k |
| plus godevmcp | 44 | ~26 KB | ~6.5k |

On the local models gallium usually drives, that is a real bite out of the
context before the conversation starts. It is also why `proxy_mcp_servers`
(PR #134) had to be opt-in per server: connecting an MCP server was
unavoidably a decision about context budget.

**The goal is to separate those two things** — which servers klein connects to,
and how much of the model's attention they cost.

## Why not the obvious alternatives

Recorded so they are not re-litigated.

- **A klein-side `ToolSearch` that loads tools, like the ReAct loop's.** Cannot
  work. "Loading" a tool there means the *next* request carries its schema; here
  there is no next request to amend.
- **A generic dispatcher (`ToolSearch` + `ToolCall(name, arguments)`).** Works
  today with no server change, but dispatched calls lose native schema
  validation — the provider validates `ToolCall`'s schema, not the inner tool's,
  so `arguments` arrives as a free-form object the model reconstructs from text
  it read a turn earlier. Weakest exactly where it would be used most: small
  local models.
- **Protocol `namespace` dynamic tools.** `DynamicToolSpec` is a union of
  `function` and `namespace` (`{type, name, description, tools}`), and
  `dynamicToolCall` carries an optional `namespace`. But gallium's
  `DynamicToolSpec` (`appserver/tools.rs:24`) parses only
  `name`/`description`/`inputSchema`, so a namespace spec deserialises to one
  empty tool with the array silently dropped. Its semantics are also
  undocumented in codex-sdk-go (`DynamicToolNamespaceTool` is `interface{}`) —
  unclear whether it defers schemas or only namespaces names. Worth revisiting:
  **if it does defer schemas, it is strictly better than what we built**, since
  it is the protocol's own answer rather than a gallium extension.

The chosen design keeps native schemas, which is what the dispatcher gave up.

## What klein now does

One boolean on each dynamic-tool entry, `advertised`, written only when false.

```jsonc
// thread/start → dynamicTools
[
  { "type": "function", "name": "LS", "description": "list a directory",
    "inputSchema": { "type": "object", "properties": { "path": {...} },
                     "required": ["path"] } },

  { "type": "function", "name": "tree_dir", "description": "[godevmcp] walk a tree",
    "advertised": false,                                  // ← the whole change
    "inputSchema": { "type": "object", "properties": { "root_dir": {...} },
                     "required": ["root_dir"] } }
]
```

Enabled by:

```toml
[appserver]
address           = "felix.local:47821"
proxy_mcp_servers = ["godevmcp"]
defer_mcp_tools   = true          # ← new, default false
```

**klein's own tools are never deferred.** Only the proxied MCP managers are, and
only when the setting asks. A turn that must discover `Read` before reading a
file has already spent more than the schema ever cost.

### Code

| Where | What |
|---|---|
| `pkg/agentserver/types.go` | `ToolSpec.Deferred bool`. Zero value advertises — the older and safer meaning, so existing callers of this package are untouched. |
| `pkg/agentserver/dynamictools.go` | `buildDynamicTools` writes `"advertised": false` only for deferred specs. |
| `internal/agentbackend/adapters.go` | `newSplitToolHost(advertised, deferred)` + `splitToolHost`. Splits **by manager**, not by a set of names, because that is how klein already knows the difference. Collapses to a plain `toolHost` when nothing is deferred. |
| `internal/agentbackend/settings.go` | `splitOfferedManagers` returns the two groups; `offeredManagers` is now their union, so existing callers and tests are unaffected. `defersMCPTools` gates on backend + setting. |
| `internal/config/settings.go` | `AppServerSettings.DeferMCPTools`. |
| `doc/CONFIGS.md` | Both `proxy_mcp_servers` (missing since #134) and `defer_mcp_tools`. |

Two invariants worth preserving, both pinned by tests:

- **Byte-identical payload when nothing is deferred.** The key is omitted, not
  written as `true`. That is what makes the flag safe to send to a server that
  has never heard of it.
- **Deferral is not authorization.** A deferred tool stays callable by name.
  `splitToolHost.Call` routes to it exactly as to an advertised one. This is a
  context-budget mechanism; anything that must *refuse* a tool has to do it in
  `Call` (as `mcpServerSubset` does).

## What gallium needs

The seam already exists and is already named. `ToolAccess` distinguishes
`descriptors()` — "the catalog" — from `get_definitions()` — "**what the model is
told it can call. A projection of the catalog**". Today that projection is 1:1.

1. **`ToolDescriptor` gains `advertised: bool`**, default true
   (`crates/gallium-agent/src/tool.rs:264`).
2. **`get_definitions()` filters on it** (`tool.rs:398`). One line, at the seam
   built for it.
3. **`DynamicToolSpec` reads the flag off the wire**
   (`appserver/tools.rs:24`) — `#[serde(default = "yes")] advertised: bool`.
4. **A native `ToolSearch` tool**: reads the full catalog via `descriptors()`,
   returns matches as text, flips them to advertised. This is the part klein
   cannot supply — klein has no way to tell gallium "now show these", and adding
   one would mean new protocol surface. gallium already has the registry.

**The one non-trivial bit:** `react_loop` hoists
`let tool_defs = tools.get_definitions();` before the loop
(`crates/gallium-agent/src/react.rs:87`), so a mid-turn change would not take
effect. It needs to move inside the `while`, or recompute on a dirty flag. That
also touches the comment below it about recording "the catalog as the model first
sees it" — the trace probably wants the *initial* projection, not the growing one.

`ToolSource` already distinguishes `Builtin` / `Mcp` / `Dynamic`, so gallium can
apply its own default policy to its own MCP tools while letting a client override
per tool.

### Suggested order

gallium 1–3 first (cheap, and makes klein's flag observable), then 4 + the
`react_loop` change together — 4 is useless without it, and 1–3 without 4 is the
dangerous state where tools go invisible with no way back.

## Verification

```bash
go build ./... && go vet ./... && go test ./...
golangci-lint run ./internal/agentbackend/... ./pkg/agentserver/...
```

All clean as of this commit. New tests:

- `pkg/agentserver`: `"advertised": false` present for deferred specs; **absent**
  for every spec when nothing is deferred; a deferred spec still carries its
  schema.
- `internal/agentbackend`: proxied tools registered-but-deferred; klein's own
  tools stay advertised; a deferred tool is still callable and reaches the live
  manager; off by default; ignored for the codex backend; the split's union
  equals `offeredManagers`.

**Not yet verified end-to-end** — gallium was unreachable when this was written,
and it does not implement the flag yet, so there is nothing to observe beyond the
payload. Once gallium ships its half:

```bash
go run ./klein --settings <cfg> "use tree_dir on the current directory"
# expect: `offering tools to the app-server count=44` unchanged (registration),
# but the model's own tool list shorter, and tree_dir reachable after a ToolSearch.
```

The existing `offering tools to the app-server count=N tools=…` log line reports
what is **registered**, which no longer equals what is advertised. If that
distinction starts mattering when debugging, that line is the place to split.

## Open questions

- **Does `namespace` defer schemas?** If yes, prefer it and drop this. Needs the
  codex protocol spec, not the generated Go types.
- **Should `proxy_mcp_servers` default to `"*"` once deferral works?** That was
  the original motivation — connection stops being a context decision. Deliberately
  *not* changed here: it would flip behaviour for existing configs based on a
  server-side feature klein cannot detect.
- **Does discovery survive a reconnect?** Thread ids do not survive a redial, so
  a reconnect starts a fresh thread and presumably resets the advertised set. The
  model would have to re-discover mid-conversation. Probably acceptable, worth
  confirming once it works.
